01 · O problema

Um único teste pode esconder muitas lacunas.

✓ passou

O teste VIP retorna R$ 80,00. O pytest está correto ao aprová-lo.

?

E o cliente comum? E o limite de R$ 500? E o valor negativo?

coverage

A ferramenta observa o que realmente foi percorrido durante a execução.

A pergunta não é apenas “o teste passou?” — é “o que ele deixou de testar?”
02 · Papéis diferentes

pytest avalia. coverage.py mede.

pytest

Descobre testes, executa funções e decide se cada asserção passou ou falhou.


Exemplo: “80 é igual a 80?”

coverage.py

Acompanha aquela execução e registra linhas e caminhos visitados.


Exemplo: “qual decisão nunca teve sua alternativa testada?”

São complementares: cobertura não substitui boas asserções; boas asserções não mostram sozinhas a abrangência.

03 · Statement × Branch

Executar a linha do if não percorre seus dois caminhos.

if idade >= 18:
    return "adulto"
else:
    return "menor"
idade = 20 → condição verdadeira → “adulto”
idade = 17 → condição falsa → “menor”

Com apenas 20, a decisão foi alcançada, mas o ramo falso não. Branch coverage procura esse segundo caminho.

08 · Demonstração obrigatória

RED → GREEN: o teste chega antes da implementação.

$ python -m pytest roteiro_live/teste_tdd_valor_negativo.py
FAILED: DID NOT RAISE ValueError

# adicionamos a validação
if valor < 0:
    raise ValueError(...)

1 passed
Por que mostrar isso?

O ciclo TDD torna a intenção explícita: primeiro definimos o comportamento esperado; depois escrevemos a menor implementação que o atende; por fim refatoramos com segurança.

09 · Limite da métrica

100% não é sinônimo de sem bugs.

Implementação errada

Uma função VIP aplica 15% de desconto, quando a regra pede 20%.

return valor * .85  # bug
Teste fraco

Ele executa todas as linhas, mas só pergunta se o resultado é positivo.

assert desconto(100) > 0
Coverage alto + asserção fraca = falsa segurança.
10 · Fechamento

Coverage é uma bússola.
Não é o destino.

Enxergue

Use a métrica para localizar lacunas.

Explore
